## WP-C (Kiosk & phone runtime) — catatan kontrak / deviasi (4 Okt 2026)

Konsumen: snapshot §5 dan endpoint publik §4.4. Semua butir **aditif**; klien tetap jalan dengan snapshot lama (tanpa `meta.version`, tanpa elemen ke-5, tanpa `rules`) dan dengan deployment tanpa API.

1. **Sumber snapshot**: kiosk/HP memuat file statis `data/directory.json`, `data/promos.json`, `data/status.json` (bukan `/api/*.json`) supaya jalan tanpa mod_rewrite dan di-cache SW. Bila `/api/version` / ping mengirim `versions.<kanal>.url`, URL itu dipakai (relatif app root). `data/directory.json?v=` boleh dilayani dari file live (query diabaikan) selama `meta.version` cocok — kiosk **menolak** prefetch bila `meta.version` ≠ versi yang diumumkan (tidak reload).
2. **Urutan polling**: `POST /api/kiosk/ping` (bila ada token) → `GET /api/version` → `GET data/version.json`. Respons 404 dari API = "API belum dipasang" → kiosk memakai `data/version.json` saja selama 10 menit (mengurangi 404). **WP-A**: `data/version.json` wajib selalu ditulis publisher (sudah).
3. **`?probe=1`**: kiosk menambahkan `probe=1` pada request versi/status/promos agar Service Worker tidak menjawab dari cache. API harus mengabaikan query yang tidak dikenal.
4. **Heartbeat** (`/api/kiosk/ping`) mengirim field tambahan: `viewport`, `kioskId`, `idle` (bool, sedang di layar atraksi), `offlineSnap` (bool, boot dari salinan localStorage). `versions.directory` = `null` untuk snapshot lama. Kiosk tanpa token tetap mengantre (maks 5.000, drop terlama) dan tidak mengirim. Respons 4xx selain 401/408/429 dianggap batch rusak → dibuang (antrean tidak macet).
6. **Beacon HP** (`/api/telemetry/phone`): `{type, k, t, a, lang, sid (dari &s= di QR), psid}`; `abandon` menambah `ci` (indeks langkah). Dikirim sebagai `application/json` lewat `sendBeacon`.

Jam operasi yang melewati tengah malam (`close < open`) diatribusikan ke hari mulai (bagian dini hari dicek terhadap hari sebelumnya) — sedikit berbeda dari pseudo-code §5.7 yang mengecek di hari yang sama. `"23:59:59"` dihitung sampai 24:00.

## WP-A (Core, DB, API, Publish) — deviasi & klarifikasi kontrak (4 Okt 2026)

Base API: `http://localhost/bsb-directory/api` (fallback tanpa mod_rewrite: `api/index.php?r=/admin/...`). Semua butir di bawah aditif kecuali disebut **deviasi**.

**Deviasi dari spec**
1. **DDL**: kolom `telemetry_events.accessible` harus di-backtick (`ACCESSIBLE` = reserved word MariaDB; DDL §3 apa adanya gagal di MariaDB 10.4). Nama kolom tetap.
2. **Seed walk edge**: `cost_override` = NULL hanya bila `round(len×unitScale,2)` **sama persis** dengan cost lama (spec: |Δ|<0,05). Hasil: 1 dari 632 edge mendapat override (Δ 0,01) → biaya rute identik 100 %.
3. **Seed URL brand**: bila outlet satu brand punya URL berbeda/kosong, `brands.url` = NULL dan tiap outlet memakai `url_override` (4 tenant) — agar outlet yang dulu tanpa URL tidak mewarisi URL outlet lain.
4. **Logo seed**: media di-dedupe SHA-256 (UNIQUE sha256,kind) → 17 tenant sekarang menunjuk file logo outlet saudara yang byte-identik (path `logo` berubah, gambar sama).
5. **Stop buntu tidak diekspor** (§5.4.6): `esc-c-ewalk-ug-2` hilang dari `amenities[]` (40 → 39); `esc-b-ewalk-ff-ewalk.connectors` kini `["esc-b-ewalk-3"]` (dulu + `esc-b-ewalk-4` yang buntu).
6. **`esc-a-penta-1` (LG↔GF)** tidak diimpor (stop LG tidak ada di data Mapplic); tercatat di `connector_banks.notes` bank `esc-a-penta` (+ landmark "depan Sociolla"). Leg GF↔UG = `L5`.
7. **Kode error tambahan**: `precondition` (428, PUT tanpa `If-Match`), `bad_request` (400), `too_large` (413), `method` (405).
8. **Login tanpa CSRF**: `POST /admin/auth/login` tidak butuh `X-CSRF-Token` (belum ada session), tetapi Origin/Referer tetap dicek. Token CSRF dikembalikan di respons login & `/auth/me`; ada juga `GET /admin/auth/csrf` (tanpa login).
9. **promos.json**: field tambahan `featuredWindows` ({tenantId:{from,to}}), `promos[].advertiser`; event `onAttract` diekspor sebagai promo `id:"e<eventId>"`, `kind:"event"`, `link:{type:"event",ref:"<id>"}`. `promos[].time` = null bila tanpa jam.
10. **status.json**: tiap closure membawa `closureId`; closure edge muncul di `closures` (key `E<id>`) **dan** `edgeOverrides` (hanya saat aktif); `notice` punya `id` & `from`. Closure terjadwal (`from` di masa depan) ikut diekspor; cron 5 menit menulis ulang status bila ada closure/notice yang mulai/berakhir.
11. `graph.rules` key `A<scheduleId>` untuk POI berjadwal (bukan per-amenity).

## Integrasi (uji stack nyata XAMPP: kiosk + HP + CMS + API, 4 Okt 2026)

Diuji dengan Chromium headless terhadap Apache/PHP/MariaDB asli (bukan mock): provisioning kiosk + heartbeat + telemetri → DB → analitik, beacon HP, edit tenant di CMS → publish → reload saat idle → rollback, closure Ops live (≤ 70 dtk, poll default), arah leg `up` → publish → restore, promo gambar → publish → hapus, offline penuh dengan SW, halaman HP dari URL QR. Perbaikan (minimal, di paket pemilik):

1. **WP-C `js/data.js` — identitas kiosk**: `kioskIdentity()` menimpa `bsb-kiosk-id` sebelum membandingkan, sehingga perangkat yang dipindah ke kiosk lain lewat `?kiosk=<id-lain>` tanpa `&key=` tetap mengirim token kiosk lama → 401 di setiap ping & flush telemetri (antrean tidak pernah terkirim; 401 dianggap bisa dicoba ulang). Sekarang id lama dibaca dulu; key tersimpan hanya dipakai untuk id yang sama, dan dihapus bila id berganti tanpa key baru.
2. **WP-A `lib/Api/CatalogApi.php` — promo/event media**: DTO mengembalikan `media:{id,url}` / `poster:{id,url}` dan UI WP-B mengirim balik bentuk yang sama, tetapi API hanya membaca `mediaId`/`posterMediaId` → simpan promo `kind:image` status aktif selalu 422 `mediaId: required_for_image` (event: gambar diam-diam tidak tersimpan). API kini menerima objek tersebut sebagai alias bila `mediaId`/`posterMediaId` tidak dikirim (`mediaIn()`).
3. **WP-A `.htaccess` root — MIME**: `mime.types` XAMPP tidak mengenal `.webp`, `.json`, `.woff2` → logo, gambar promo, snapshot JSON, dan font terkirim **tanpa** `Content-Type` padahal `X-Content-Type-Options: nosniff` aktif. Ditambah `AddType` untuk `image/webp`, `application/json`, `font/woff2`, `video/mp4`.

Catatan (bukan bug, tidak diubah):
- Tidak ada kiosk UG yang rute terbaiknya ke GF lewat Eskalator A Pentacity (kiosk UG Pentacity ke GF lewat Eskalator B), jadi uji DoD "UG→GF tidak lewat eskalator A" memakai Router kiosk dari tenant UG terdekat dengan stop UG Eskalator A.
- Halaman HP menghormati closure (rute memutar lewat lift) tetapi tidak menampilkan kalimat pemberitahuan detour seperti di kiosk.
- `GET /publish/preview?channel=promos` selalu melaporkan `sectionsChanged:["promos"]` (by design); indikator "belum dipublish" memakai `/auth/me.unpublished`.
- Rollback hanya mengganti file live (draft DB tetap) — sesuai §2.14; data uji di draft dikembalikan manual lalu dipublish.
- Perubahan `js/data.js` tidak menaikkan `APP_BUILD`; SW memakai stale-while-revalidate untuk `js/`, jadi kiosk mendapat versi baru pada muatan berikutnya. Naikkan `APP_BUILD` saat deploy produksi bila ingin langsung.
