## 2. Coordinate transform (verified)

Mapplic stage = `mapWidth × mapHeight` = **1000 × 800**. Each layer SVG is drawn into that stage with
`preserveAspectRatio="xMidYMid meet"` (letterboxed, centred). Location `coord` is normalised to the stage; route `points`
are stage pixels ("map px"):

```
X = coord.x * 1000 ;  Y = coord.y * 800                     (route points are already X,Y)
s  = min(1000 / vbW, 800 / vbH)                              (1920x1080 -> 0.520833)
ox = (1000 - vbW*s)/2 ; oy = (800 - vbH*s)/2                  (1920x1080 -> 0, 118.75)
svgX = vbMinX + (X - ox)/s ;  svgY = vbMinY + (Y - oy)/s      (1920x1080 -> 1.92*X, 1.92*(Y-118.75))
```

Verification: every floor was rendered with all routes and markers on top (`data/debug/*.png`). Markers sit on their
storefronts (Starbucks, Uniqlo, H&M, KFC and Hypermart logos), route polylines run inside corridors, and 329/329 tenant
routes start within 3 map px of their marker. The route's **first** vertex is the location, because Mapplic draws routes
from the location outward. Connectors follow the same rule: the first vertex is the escalator or lift.

`lg-ewalk.svg` is a Cairo export with viewBox `0 0 266 150`. It is wrapped in `<g transform="scale(7.218)">` and its
viewBox is set to `0 0 1920 1082.71`, so all 8 floors are about 1920 units wide.

## 3. Floors: kept as 8 separate floor entries

GF and UG are single SVGs that show the **whole site** (both buildings + parking) at a small scale. LG, 1F and 2F have one
**zoomed-in SVG per building**. Merging them would mean inventing a transform between unrelated drawings, so each Mapplic
layer stays its own floor entry with `level` (-1 LG, 0 GF, 1 UG, 2 1F, 3 2F) and `building`
(`pentacity` | `ewalk` | `both`). Extra fields the UI can use:

- `focus`: per-building bounding box `[x,y,w,h]` in that floor's SVG space, for camera framing. On GF/UG the buildings are
  small, so the UI should zoom to `focus[building]`.
- `unitScale`: the detail drawings are 3–6× more zoomed in than GF/UG. Walking cost = SVG length × `unitScale`, which makes
  costs comparable across floors (unit = GF/UG SVG unit). It is estimated as the geometric mean of distance ratios between
  the same lift/escalator banks on that floor vs. GF (for LG) or UG (for 1F/2F). Treat it as approximate (±30 %). 2F E-Walk
  has only one bank, so it uses the E-Walk average. Values: lg-penta .337, lg-ewalk .360, ff-penta .217, ff-ewalk .227,
  sf-penta .162, sf-ewalk .294.

Building on combined floors: E-Walk is the north-east block. Split rule on map px: `X − 0.6·Y ≥ 375` → E-Walk
(the nearest tenants of the two blocks are at 347 and 401). Checked visually in the debug images (blue = Pentacity, orange = E-Walk).

  brand goes in `brand`, so search results can be grouped.
- **Same floor + same building duplicates → merged**:
  - `"Skechers  "` (UG Pentacity, next to Planet Sports) dropped; `"Skechers "` (between Andalas and Adidas) kept, because the
    old per-building map has only that one. ⚠ confirm with the mall.

- **Categories**: 8 ids: `food-beverage, fashion, beauty-health, electronics, kids-family, entertainment, department-store,
  services` (icons are lucide icon names). Source groups map 1:1, `Gadget` is merged into electronics, every uncategorised
  real tenant got a category by hand, and obvious misfiles were fixed (list in §B).
- **Links**: `https://` only. Redirect targets from the URL audit are used. Tracking params (`utm_*`, `srsltid`, `gad_*`,
  `gclid`, `gbraid`, `igshid`, `igsh`, `hl`) are removed. Google `aclk` ad links are replaced by their landing page. Phone
  numbers found in the link field moved to `phone` (The Body Shop, Fore). Wrong-brand links were fixed only where a

  Crocs→crocs.co.id). Unreachable links are `null`: Wrangler, Little X.Eight, Kidz Station, Erha (404), Ramen 1, Yoshinoya

  those links are kept. Every final URL was checked a second time: `data/raw/https_check.tsv`.

- **keywords**: generated for search (Indonesian + English synonyms by brand type and category, plus floor/building).
- **Logos**: the Starbucks Pentacity image field held two URLs glued together (the 2nd one 404s), so the first URL is used.
  The Java Kulit logo comes from the old-map entry. Food Court had the XXI logo in the old map, so it gets no logo.

## 5. Graph construction

- Input is every route polyline on the 8 real layers. Vertices within **1.0 map px** are snapped to one node, and 5
  T-junctions were spliced (a dangling end within 1 px of another segment).
- Connectors: routes with `connect:true` that share an `endpoint` are joined between their first vertices.
  - Escalators → two directed edges (`escalator-up` lower→upper, `escalator-down` upper→lower). The real direction is not
    in the data, so both directions exist.
  - Lifts → a chain between consecutive levels.
  - `cross-ff` → a `crossing` edge (the 1F bridge).
- Costs: walk = euclidean SVG length × `unitScale`. Inter-floor = Mapplic `weight` × 1.92 per level (escalator weights are
  10–20). In the source, lifts are *cheaper* than escalators (weight 2–5), which made every route use the lift, so lifts
  are floored at weight 20 per level. Crossing = 0 + the walking length of the bridge polyline.
- Tenants: node = first vertex of the route whose `endpoint` = location id (204 tenants). 3 tenants had a single-point route
  and 3 points had no route at all; they are attached by projecting onto the nearest corridor (list §G). 2 escalator ends
  drawn as single points were joined the same way.
- Contract: `edges` = `[from, to, cost, type]`. walk/lift/stairs/crossing edges are undirected; escalator-* edges are directed.
- Tenant unit shapes: tagged in the floor SVG as `id="unit-<tenantId>"`, `data-tenant="<tenantId>"`, class `unit` (list §E).
  All other SVG ids are prefixed `<floorId>--` so several floors can be inlined in one DOM.

## 6. Problems NOT resolved (need the mall / a map editor)

1. **2F E-Walk has almost no corridors** in Mapplic (only the escalator stub). Grand Jatra Hotel (151 px away) and
   Cinema XXI 2F (228 px away) are reached by straight stubs across the atrium. They work, but the paths are approximate.
2. **No lift on 2F E-Walk** in the data, so accessible mode cannot reach Matahari 2F, XXI 2F or Grand Jatra Hotel.
3. **Dangling escalators**: `esc-b-ewalk-4` exists only on 1F E-Walk (its 2F end is missing); `esc-c-ewalk-3` exists only
   on UG (its 1F end is missing). They are listed as amenities but lead nowhere.
4. **No direct LG Pentacity ↔ LG E-Walk link** in the data; routes go up to GF and back down. The 1F bridge is the only
   explicit crossing; on GF/UG the buildings are connected by ordinary corridors on the combined plan.
5. Mapplic does not link SVG elements to locations (no SVG id equals a location id). 52 units were matched heuristically
   (marker inside a shape of the Illustrator `tenant` group) on LG/1F/2F Pentacity and 1F/2F E-Walk. GF, UG and LG E-Walk
   have no tenant group and their markers sit in the corridor, so there is no unit highlighting on those floors.
6. `lg-ewalk.svg` is still 0.93 MB (Cairo-outlined text; there is no editor junk to strip).
7. Some data is probably stale: shops may have closed or moved, and the source has no "last updated" field. Toilets,
   prayer rooms, ATMs, parking entrances and the information desk are not on the map at all.
